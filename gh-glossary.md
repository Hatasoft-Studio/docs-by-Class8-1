| 英文术语            | 中文翻译            | 用途                                 | 基础操作                                      |
| ------------------- | ------------------- | ------------------------------------ | --------------------------------------------- |
| Repository（Repo）  | 仓库                | 存放整个项目全部文件、版本记录       | 浏览项目文件，查看历史改动                    |
| Owner               | 仓库所有者          | 拥有仓库最高管理权限                 | 可以合并 PR、设置仓库、管理成员               |
| Organization（Org） | 组织                | 用于存放团队多人项目                 | 创建组织，添加团队成员，管理团队仓库          |
| Fork                | 复刻                | 复制别人仓库到自己账号，用来修改贡献 | 点仓库页面 Fork 按钮，生成自己的副本仓库      |
| Clone               | 克隆                | 将远程仓库下载到本地电脑             | 复制仓库地址，在 Git 工具执行 clone 命令      |
| Local               | 本地                | 电脑上存放的项目文件                 | 在本地修改文件，离线编辑                      |
| Remote              | 远程                | GitHub 服务器上保存的项目            | 上传本地改动，拉取线上最新文件                |
| README              | 自述文件            | 项目首页介绍文档，说明项目信息       | 编辑`README.md`，写入项目介绍、使用方法       |
| LICENSE             | 许可证              | 规定他人使用项目文件的权限           | 新建 / 编辑 LICENSE 文件，选择开源协议        |
| .gitignore          | Git 忽略配置文件    | 设置不需要上传的文件                 | 编辑`.gitignore`，填写要忽略的文件名称        |
| Template repository | 模板仓库            | 快速新建结构相同的新项目             | 将仓库设为模板，一键创建新项目                |
| Archive             | 归档                | 将仓库设为只读，不再接受更新         | 仓库设置里执行归档操作                        |
| Branch              | 分支                | 独立开发线路，隔离不同修改           | 创建分支，切换分支进行修改                    |
| main                | 主分支              | 存放项目稳定正式代码                 | 一般不在主分支直接大量修改                    |
| master              | 主分支              | 旧版 GitHub 默认主分支名称           | 新版项目推荐改用 main 分支                    |
| Feature branch      | 功能分支            | 专门开发新功能的分支                 | 从主分支新建分支，在上面开发功能              |
| Checkout            | 切换分支            | 在本地切换到不同分支                 | 使用 Git 命令切换分支                         |
| Commit              | 提交                | 保存一次改动，生成版本快照           | 修改文件后填写提交说明，执行提交              |
| Commit message      | 提交说明 / 提交日志 | 记录本次修改内容                     | 提交时填写一句话描述改动                      |
| Commit hash         | 提交哈希            | 唯一标识每一次提交                   | 通过哈希查看某次提交的详细改动                |
| Tag                 | 标签                | 标记项目发布版本，如 v1.0.0          | 在仓库创建标签，绑定指定提交版本              |
| Snapshot            | 快照                | 项目某一时间点文件完整存档           | 每次 Commit 自动生成快照                      |
| Pull Request（PR）  | 拉取请求            | 将自己副本的修改申请合并到原项目     | 点击 Compare & pull request，填写标题内容提交 |
| Merge               | 合并                | 把分支改动并入目标分支               | 维护者审核后点击 merge 合并 PR                |
| Merge conflict      | 合并冲突            | 多人修改同一位置，Git 无法自动合并   | 打开冲突文件，手动选择保留内容                |
| Push                | 推送                | 把本地 commit 上传到远程仓库         | Git 执行 push，上传本地改动                   |
| Pull                | 拉取                | 把远程最新代码下载合并到本地         | Git 执行 pull，同步线上更新                   |
| Fetch               | 获取                | 下载远程更新，不自动合并             | Git 执行 fetch，查看远程变更后手动合并        |
| Compare             | 对比                | 查看两个版本 / 分支之间的文件差异    | 打开 Compare 页面，查看修改前后对比           |
| Issue               | 议题                | 反馈 bug、提功能建议、项目讨论       | 点击 New Issue，填写标题和内容提交            |
| Bug                 | 缺陷 / 漏洞         | 程序或文档存在的错误                 | 新建 Issue，描述 bug 现象                     |
| Feature request     | 功能需求            | 向项目提出新增功能建议               | 在 Issue 中描述想要增加的功能                 |
| Label               | 标签                | 给 Issue、PR 做分类标记              | 创建标签，给 Issue/PR 打上对应标签            |
| Milestone           | 里程碑              | 把一批 Issue 规划到某个版本完成      | 创建里程碑，将 Issue 关联到里程碑             |
| Assignee            | 被指派者            | 指定负责处理该 Issue/PR 的人         | 在 Issue/PR 页面选择指派人员                  |
| Review              | 评审 / 代码审查     | 检查别人提交的 PR，给出修改意见      | 打开 PR，查看文件，写评审意见                 |
| Comment             | 评论                | 在 Issue 或 PR 下面留言讨论          | 在评论框输入文字提交                          |
| Draft PR            | 草稿拉取请求        | 还没完成，暂不接受正式审核的 PR      | 创建 PR 时勾选草稿，完成后标记就绪            |
| Star                | 标星                | 收藏、关注项目，表示支持             | 仓库主页点击 Star 按钮                        |
| Watch               | 关注                | 订阅仓库动态，接收通知               | 仓库主页点击 Watch                            |
| Fork count          | 复刻数量            | 该仓库被别人 Fork 的总次数           | 仓库页面直接查看数字                          |
| Release             | 发布版              | 打包项目，提供下载包                 | 创建 Release，绑定 Tag，上传压缩包            |
| Pre-release         | 预发布版            | 测试版本，不建议正式使用             | 创建 Release 时勾选预发布选项                 |
| Wiki                | 维基（项目知识库）  | 存放项目详细文档教程                 | 进入 Wiki 页面，新建、编辑文档                |
| GitHub Pages        | GitHub 静态网页托管 | 免费托管项目网页                     | 在仓库设置开启 Pages，指定文件来源            |
| Workflow            | 工作流              | GitHub 自动化任务配置                | 编写 yaml 文件，配置自动打包、测试            |
| GitHub Actions      | GitHub 自动化动作   | 执行自动化构建、测试、部署           | 触发工作流，自动运行脚本                      |
| Artifact            | 构建产物            | 自动化打包生成的文件                 | Actions 运行完成后下载产物文件                |
| Secret              | 密钥                | 仓库保存的保密变量，不会公开         | 在仓库设置添加密钥，给工作流调用              |
| Contributor         | 贡献者              | 给项目提交过修改的人                 | 提交 PR 被合并后，成为贡献者                  |
| Maintainer          | 维护者              | 负责管理仓库、审核 PR 的人员         | 拥有仓库管理权限，处理贡献提交                |
| Upstream            | 上游仓库            | 原始的官方项目仓库                   | Fork 后的仓库可拉取上游最新代码               |
| Downstream          | 下游仓库            | Fork 出来的副本仓库                  | 从上游仓库复制而来，用于修改贡献              |
